# 网页访问与手机工作区

Core 在 Windows 电脑上运行插件后端，通过内置 HTTP 服务提供手机与其他设备的 WebUI。无需安卓客户端。服务默认关闭，每次开启生成新的 256 位随机访问密钥；关闭或退出 Core 后失效，重启不会自动开启。当前版本不提供后台 Windows 服务，电脑需保持开机且 Core 仍在运行（可以收起到托盘）。

## 局域网

1. 在桌面“设置 → 网络 → 网页访问”选择“局域网”，端口默认 `17890`。
2. 勾选允许远程使用的已运行插件，点击“开启网页访问”。没有勾选插件时，可访问空工作区。
3. Core 自动读取已连接网卡的 IPv4，生成完整访问网址，每 5 秒刷新。多网卡、VPN 或虚拟网卡环境下，在“手机 / 其他设备访问地址”选择与手机网络相通的地址，私有地址优先排列。
4. 点击“显示连接二维码”，用手机相机扫码打开即可自动连接；也可以复制网址和密钥，手动输入。

二维码在本机生成，不使用第三方二维码服务。它包含完整网址和当前临时密钥，密钥位于 URL 的 `#connect=…` 片段中，不会出现在 HTTP 请求、代理访问日志或 Referrer 中。手机页面在路由初始化前取出密钥并立即清除地址栏片段；二维码和“快速连接链接”本身仍是访问凭据，扫描器或聊天软件可能保留原始链接，勿公开分享。关闭服务后原二维码失效。

回环、断开、未指定、链路本地和组播地址不会作为连接候选；当前监听为 IPv4，不展示 IPv6。没有可用地址时会提示连接网络或配置 HTTPS 入口，不会把 `127.0.0.1` 作为手机地址。候选列表来自本机网卡，不进行外网探测，不保证手机到该网卡之间的网络可达性。

局域网模式监听 `0.0.0.0` 的全部 IPv4 接口，包含可能存在的公网接口。请将防火墙规则限定到需要的网络；Core 不会自动修改 Windows 防火墙、路由器端口转发或 UPnP。HTTP 仅适用于可信局域网。访客 Wi-Fi、AP 隔离和防火墙可能阻止设备互访。

## 公网、反向代理与内网穿透

采用独立 HTTPS 域名的根路径，例如 `https://core.example.com/`。在 Core 选择“仅本机”，由同机反向代理或穿透代理连接 `http://127.0.0.1:17890/`。如果代理位于另一台主机或容器，其 `127.0.0.1` 不代表 Core 所在电脑，需选择局域网模式并使用电脑地址，限制网络访问范围。

“公网 HTTPS 入口”是给用户展示的访问地址，不会创建 DNS、证书、隧道或端口映射。将现有的 HTTPS 反向代理、frp HTTPS 入口或 Cloudflare Tunnel 等穿透工具指向 Core 监听地址。Core 不代管这些工具的账号和凭据。

例如已有 Caddy 及正确 DNS 时，可使用以下配置（域名为示例，必须替换）：

```caddyfile
core.example.com {
    reverse_proxy 127.0.0.1:17890
}
```

代理必须转发完整路径、查询参数和 `Authorization` 请求头，不要缓存 `/api/*`、`/plugin-assets/*`。目前不支持 `/wonderland/` 这样的子路径部署。事件使用带密钥的 HTTP 轮询，无需 WebSocket 配置。不要把 Core 的明文 HTTP 端口直接暴露到公网。

## 桌面 / 手机界面与能力范围

- 同一个访问网址按浏览器可用宽度自动适配。宽度达到 1024px 时使用桌面 Core 风格的可折叠侧栏、多列工具卡片与插件页签，并显示连接地址、状态和 Core 版本；较窄窗口使用触屏按钮、底部导航和页面选择器。两种布局均支持工具搜索、深浅色主题，手机支持安全区适配。
- 调整窗口宽度只改变布局，不重建插件页面，保留当前插件的临时状态。桌面 WebUI 使用远程共享的能力范围，Core 的本机设置仍需在宿主机管理。
- 桌面和手机工作区入口列表按插件去重：优先选择 `defaultOrder` 最小的 Activity，同序以 ID 排序；没有 Activity 时使用首个 View。手机中其他 Activity / View 放在插件内部“插件页面”切换器中，不再单独占一张卡片。已访问的辅助页与主页面保持挂载，支持跨页面事件同步。
- 后端仍使用同一 Core 的插件进程与数据，浏览器支持调用、取消、事件、主题同步和沙箱握手。
- 连接后浏览器仅在当前页面内存中保存访问密钥；刷新、断开连接或服务撤销后需重新输入或扫描仍有效的二维码。密钥不放在查询参数、Cookie 或 localStorage 中。
- 远程白名单按插件授权，不按单个方法授权。持有同一密钥的设备共享插件权限和业务事件；已有宿主能力授权仍然有效。文件和系统交互由 Core 按调用上下文调度，交互项与下载内容额外绑定当前浏览器连接，不广播到其他设备。
- 远程不开放 Core 的账号管理、插件安装／授权、文件系统、应用更新或窗口 IPC。需要新增白名单或换密钥时，在电脑关闭服务后重新开启。
- 关闭服务会拒绝后续请求并撤销资源链接。已经提交给插件的任务不保证随服务关闭而终止，请通过插件本身取消任务。
- 插件前端保持独立维护。Core 手机外壳已适配窄屏，但插件自己的桌面布局、文件选择、剪贴板、下载等功能可能需要插件进一步适配；当前不生成原生 Android 安装包，也不提供离线 PWA。

## 远程文件与系统交互

| 操作 | 宿主机本地工作区 | 远程 WebUI |
| --- | --- | --- |
| 导入配置、CSV、背景图片 | 原有系统文件选择框及读取流程 | Core 页面显示文件面板，从访问设备选择；按需分块传给插件 |
| 导出 JSON、CSV、XLSX | 原有宿主机导出目录 | 文件面板点击“准备下载”，再“保存到本设备”；不写宿主机导出目录 |
| 打开导出目录 | 原有系统文件管理器 | 提示在远程文件面板下载 |
| 打开插件数据目录 | 原有系统文件管理器 | 明确提示需要在宿主机操作 |
| 打开 Core 允许的官网链接 | 原有系统浏览器 | 文件面板提供当前设备可点击的链接，仍使用同一地址白名单 |

文件选择等待最多 45 秒（还受插件方法自身超时约束），可取消；取消、调用结束或服务关闭会释放等待，父调用取消会传递到下游服务。远程单个导入文件最多 128 MiB，插件要求更小时使用其限制；一次调用最多同时持有 8 个文件。读取每块最多 1 MiB，整文件读取仍限制为 20 MiB。导出保持原有 20 MiB 单文件上限，Core 全部待下载内容合计最多 64 MiB、交互项最多 64 个。下载项保留 5 分钟，可重复下载或手动移除；移除后浏览器释放已准备的文件内容。刷新页面后连接身份改变，旧下载项不会转交给新连接。

浏览器只传文件名、大小与字节，不提供可由 Core 打开的宿主机路径。下载需要用户点击，避免手机浏览器拦截异步下载。剪贴板仍由插件页面在访问设备上处理，Core 不把宿主机剪贴板转发到远程；LAN HTTP 和浏览器权限导致的限制由插件提供文本选中复制等降级方式。

### 插件接入与旧版本

调度由 Core 统一实现，插件继续调用 `core.files.*` 和 `core.browser.open_official`。本次后端 SDK 自动在每个派生 `HostClient` 中保留并回传 Core 发出的 `serviceContext`；不按插件全局状态猜测来源，因此本地和不同设备的并发调用各自独立。远程宿主服务由受限工作线程执行（每个插件最多 16 个），浏览器文件选择等待不会阻塞 Core 读取该插件的其他响应；插件后端自身是否并发仍取决于其实现。本地宿主服务保留原有同步路径。服务间调用也传递远程上下文。后台任务应使用所属调用的 `HostClient`，不要使用跨调用缓存的客户端处理文件交互。

重新构建插件后，在 manifest 的 `backend` 中声明 `"supportsServiceContext": true`。自实现协议的后端必须把请求中的可选 `serviceContext` 原样带到对应的 `core.*` 请求中；无该字段时维持旧消息格式。富文本编辑器已补上透传，其余 SDK 插件只需随新 SDK 重建并更新声明。不要给未更新的二进制单独添加此声明。

旧插件在本地仍按原流程工作。未声明上下文支持的插件会被拒绝远程调用并提示升级，避免超时或并发时误操作宿主机。新字段及调度需要本次更新后的 Core，已发布的 0.1.7 不支持；正式发布配套插件时须把 `minCoreVersion` 提升到承载此功能的 Core 版本。业务数据仍属于宿主机插件，导入会按插件原有逻辑更新这些数据。

## CLI

命令必须发送到正在运行的桌面 Core；可用全局 `--data-dir <绝对路径>` 指定独立测试 profile。

```powershell
# PowerShell 7 示例；按实际安装位置调用 wla.exe。
$webOptions = @{
    mode = 'loopback' # 或 'lan'
    port = 17890
    publicUrl = 'https://core.example.com/' # 不使用公网时为空字符串
    pluginIds = @('rich_editor') # 必须已经安装、启用并运行
} | ConvertTo-Json -Compress
wla web start --config-json $webOptions --yes
wla web status
wla web stop --yes
```

`start` 和 `status` 输出包含访问密钥，勿保存到共享日志。局域网模式下还返回 `lanAddresses`（网卡名、IPv4、完整 URL）；枚举失败时返回 `addressError`，服务本身仍可继续运行。`stop` 可以重复执行；已开启时再次 `start` 会返回错误，避免意外中断已连接设备。端口占用、非法 HTTPS 入口、未运行插件会返回明确错误。

## 开发与检查

```powershell
pnpm --filter @wonderland/desktop-ui run build
cargo test --workspace --locked
pnpm -r run test
pnpm dev
```

Vite 同时构建 `index.html`（桌面）和 `mobile.html`（浏览器），生产版由 Tauri 的嵌入式资源提供，无需另行部署静态目录。Debug 模式的网页服务从 `ui/dist` 读取资源，因此需先运行前端 build，修改后再次 build 并刷新手机页。

HTTP API 位于 `/api`：`GET status/plugins/launch/{pluginId}/events`、`POST call/cancel`。所有 API 都要求 Bearer 密钥；请求体限制 256 KiB，最多 16 个并发插件调用。事件缓存最多 256 条、每条最多 64 KiB，落后于缓存时 UI 提示重新打开工具。插件资源使用独立临时资源授权，继续沿用路径校验、CSP 和 `sandbox="allow-scripts"`，不会获得 API 密钥。

远程文件另有 `GET interactions`、`POST interactions/{id}/reply` 和 `GET interactions/{id}/content`。这些接口与远程调用携带每次连接新生成的 `X-Wonderland-Client` 标识，仅通过请求头传送；文件交互不进入共享业务事件流。只有 reply 的请求体上限为 2 MiB，以容纳 1 MiB 文件分块的 base64，其余调用保持 256 KiB。

回归检查包括：无密钥与错误密钥被拒绝、白名单隔离、路径限制、密钥撤销、旧请求不影响新连接、插件沙箱加载与实际读写，以及 390px 手机和宽屏工作区显示。真实公网可达性还取决于实际部署的域名、TLS、代理与网络环境。

## 本次代码审查修复

- P2：旧的连接请求完成或失败时可能覆盖／断开新连接。连接过程和数据响应现在都绑定连接代次，过期结果丢弃，新增并发登录回归测试。
- P2：手机打开辅助 View 会卸载主 Activity，跨页面发布事件没有接收者。现在保留同一插件已访问的页面，隐藏页继续接收事件，离开该插件时统一卸载。
- P2：设置页较慢的轮询可能用旧状态覆盖刚完成的开启／关闭操作。变更时使在途轮询失效，并暂停新轮询。
- P2：超过事件大小上限的消息被静默丢弃，客户端无法发现缺失。现在为已分享插件的丢失事件记录序号缺口，让手机提示重新打开页面刷新状态。

新增回归还覆盖二维码片段消费与清除、非法链接、单插件入口选择、网卡过滤／排序／去重和完整 URL 生成。二维码不延长权限有效期，关闭后仍遵循原有密钥撤销流程。
