# 网页访问与手机工作区

Core 在 Windows 电脑上运行插件后端，通过内置 HTTP 服务提供手机与其他设备的 WebUI。无需安卓客户端。服务默认关闭，访问密钥可选：留空可直接连接，填写后启用认证，也可以点击“生成随机密钥”。关闭或退出 Core 后服务停止，重启不会自动开启。当前版本不提供后台 Windows 服务，电脑需保持开机且 Core 仍在运行（可以收起到托盘）。

## 局域网

1. 在桌面“设置 → 网络 → 网页访问”选择“局域网”，端口默认 `17890`。
2. 勾选允许远程使用的已运行插件；按需填写访问密钥，留空可直接连接。点击“开启网页访问”。没有勾选插件时，可访问空工作区。
3. Core 自动读取已连接网卡的 IPv4，生成完整访问网址，每 5 秒刷新。多网卡、VPN 或虚拟网卡环境下，在“手机 / 其他设备访问地址”选择与手机网络相通的地址，私有地址优先排列。
4. 点击“显示连接二维码”，用手机相机扫码打开即可自动连接；也可以复制网址和密钥，手动输入。

二维码在本机生成，不使用第三方二维码服务。未设置密钥时二维码仅包含网址；设置密钥时，密钥位于 URL 的 `#connect=…` 片段中，不会出现在 HTTP 请求、代理访问日志或 Referrer 中。手机页面在路由初始化前取出密钥并立即清除地址栏片段；二维码和“快速连接链接”本身仍是访问凭据，扫描器或聊天软件可能保留原始链接，勿公开分享。关闭服务后无法连接；再次开启并使用相同地址和密钥时，可继续使用原链接。

回环、断开、未指定、链路本地和组播地址不会作为连接候选；当前监听为 IPv4，不展示 IPv6。没有可用地址时会提示连接网络或配置 HTTPS 入口，不会把 `127.0.0.1` 作为手机地址。候选列表来自本机网卡，不进行外网探测，不保证手机到该网卡之间的网络可达性。

局域网模式监听 `0.0.0.0` 的全部 IPv4 接口，包含可能存在的公网接口。请将防火墙规则限定到需要的网络；Core 不会自动修改 Windows 防火墙、路由器端口转发或 UPnP。HTTP 仅适用于可信局域网。访客 Wi-Fi、AP 隔离和防火墙可能阻止设备互访。

## 公网、反向代理与内网穿透

采用独立 HTTPS 域名的根路径，例如 `https://core.example.com/`。在 Core 选择“仅本机”，由同机反向代理或穿透代理连接 `http://127.0.0.1:17890/`。如果代理位于另一台主机或容器，其 `127.0.0.1` 不代表 Core 所在电脑，需选择局域网模式并使用电脑地址，限制网络访问范围。

“公网 HTTPS 入口”是给用户展示的访问地址，不会创建 DNS、证书、隧道或端口映射。将现有的 HTTPS 反向代理、frp HTTPS 入口或 Cloudflare Tunnel 等穿透工具指向 Core 监听地址。Core 不代管这些工具的账号和凭据。

例如已有 Caddy 及正确 DNS 时，可使用以下配置（域名为示例，必须替换）：

```caddyfile
core.example.com {
    reverse_proxy 127.0.0.1:17890
}
```

代理必须转发完整路径、查询参数、`Authorization` 和 `X-Wonderland-Key`，保留下载所需的 Cookie／Set-Cookie；不要缓存 `/api/*`、`/plugin-assets/*`、`/downloads/*`。目前不支持子路径部署。事件使用 HTTP 轮询，无需 WebSocket 配置。

## 桌面 / 手机界面与能力范围

- 同一个访问网址按浏览器可用宽度自动适配。宽度达到 1024px 时使用桌面 Core 风格的可折叠侧栏、多列工具卡片与插件页签，并显示连接地址、状态和 Core 版本；较窄窗口连接后使用单行紧凑工具栏，将返回工作区、当前页面选择和选项菜单放在同一行，不再显示重复的品牌栏和底部导航。连接状态、地址、Core 版本、主题切换和断开连接位于右上角选项菜单，插件内容占据剩余高度。两种布局均支持工具搜索、深浅色主题，手机支持安全区适配。
- 调整窗口宽度只改变布局，不重建插件页面，保留当前插件的临时状态。桌面 WebUI 使用远程共享的能力范围，Core 的本机设置仍需在宿主机管理。
- 桌面和手机工作区入口列表按插件去重：优先选择 `defaultOrder` 最小的 Activity，同序以 ID 排序；没有 Activity 时使用首个 View。手机中其他 Activity / View 放在插件内部“插件页面”切换器中，不再单独占一张卡片。已访问的辅助页与主页面保持挂载，支持跨页面事件同步。
- 后端仍使用同一 Core 的插件进程与数据，浏览器支持调用、取消、事件、主题同步和沙箱握手。启用且待用的插件可以共享，设置共享和查询目录不启动它；经过认证、共享范围和方法校验的真实打开／调用才激活。未共享、停用及 localOnly 请求在激活前拒绝。
- 远程仅在首次访问贡献点时挂载页面；后端启动失败显示具体错误并允许显式重试。GET /api/launch/{id} 携带 requestId 和可选 retry，等待及取消归属当前 client；其他设备不能取消该等待。已生成下载仍按原文件归属领取，旧文件选择必须绑定存活的实例。
- 连接成功后，浏览器按当前站点在 localStorage 中记住密钥和服务会话；刷新、关闭后重新打开页面会自动连接。密钥被服务器拒绝或点击“断开连接”时清除对应记录；短暂断网保留记录。无密钥服务可自动进入。浏览器禁止存储时降级为当前页面内存，不影响连接。密钥不放在查询参数或 Cookie 中。
- 远程共享范围按已选根插件控制，能够连接的设备使用这些插件并接收其业务事件。普通宿主服务默认可用；远程跨插件调用与交互沿根插件的声明依赖传递，未声明的目标或方法明确失败。文件和系统交互由 Core 按调用上下文调度，交互项与下载内容额外绑定当前浏览器连接，不广播到其他设备。
- 远程不直接开放插件安装、应用更新或主窗口 IPC。插件业务由插件管理；my_wonderland 的账号凭据保存在宿主插件数据中，远程仅查看及采集。contract 中 localOnly:true 的方法在直接与依赖调用两条路径都不可远程执行，通用浏览器会话也不会替远程设备打开宿主登录窗。需要新增共享插件或换密钥时，在电脑关闭服务后重新开启。
- 关闭服务会拒绝后续请求并撤销资源链接。已经提交给插件的任务不保证随服务关闭而终止，请通过插件本身取消任务。
- 插件前端保持独立维护。Core 手机外壳已适配窄屏，但插件自己的桌面布局、文件选择、剪贴板、下载等功能可能需要插件进一步适配；当前不生成原生 Android 安装包，也不提供离线 PWA。

## 远程文件与系统交互

| 操作 | 宿主机本地工作区 | 远程 WebUI |
| --- | --- | --- |
| 导入配置、CSV、背景图片 | 原有系统文件选择框及读取流程 | Core 页面显示文件面板，从访问设备选择；按需分块传给插件 |
| 导出 JSON、CSV、XLSX | 自身 Exports 目录 | 文件面板点击“准备下载”，再“交给浏览器保存” |
| 显式路径读写 | Core 宿主文件系统 | 同样指向 Core 宿主，不指向手机磁盘 |
| 打开导出目录 | 原有系统文件管理器 | 提示在远程文件面板下载 |
| 打开插件数据目录 | 原有系统文件管理器 | 明确提示需要在宿主机操作 |
| 打开插件指定的 HTTP(S) 链接 | 原有系统浏览器 | 文件面板提供当前设备可点击的链接，与本地使用同一 URL 格式校验 |

文件、网络与流没有固定总量和总期限；旧 45 秒选择等待、20／128 MiB 文件总量、64 MiB 总缓存和 5 分钟活跃传输寿命限制已移除。插件可设置过滤和显式期限；单块 1 MiB、帧预算、队列和并发容量仍用于资源调度。取消、调用结束及服务停止释放相应等待和引用。

“准备下载”通过普通认证请求 POST `/api/interactions/{id}/prepare` 取得同源原生下载 URL 和 HttpOnly 下载 Cookie。浏览器 GET `/downloads/...` 时按分享 session、client、action、nonce 和 Cookie 校验并流式返回，不先聚合整个响应为 Blob。Cookie 只用于下载，不替代普通 API 认证；链接本身不携带主连接密钥。

未领取内容保留并阻止升级，直到领取或明确移除；不保证跨重启恢复。服务器传输完成不证明浏览器落盘。宿主可用 `wla web downloads list` 查看遗留交付，`wla web downloads discard <download-id> --yes` 移除并停止活动传输，不删除用户原文件。

文件 owner 的 `{sessionId,clientId}` 单独存于 sessionStorage，不在该记录保存访问密钥。同分享 session 的同标签刷新／重连可恢复待领 owner；普通新标签生成不同身份。复制标签可能克隆存储，同浏览器 profile 又共享 Cookie，因此不承诺严格设备／标签绑定。存储不可用时只保留内存身份。

断开通过 POST `/api/downloads/revoke` 撤销下载 owner。未确认的撤销须先重试，不能先恢复同 owner 再异步撤销新登记；旧响应按连接代次丢弃。关闭页面可能丢失未确认撤销的内存重试记录，遗留下载由宿主显式处理。

浏览器只传文件名、大小与字节，不提供可由 Core 打开的宿主机路径。下载需要用户点击，避免手机浏览器拦截异步下载。剪贴板仍由插件页面在访问设备上处理，Core 不把宿主机剪贴板转发到远程；LAN HTTP 和浏览器权限导致的限制由插件提供文本选中复制等降级方式。

### 插件接入与旧版本

调度由 Core 统一实现，插件调用 `core.files.*`、`core.browser.open {url}` 和 `core.plugins.call`。后端 SDK 在每个派生 `HostClient` 中保留并回传 Core 发出的 `serviceContext`；本地和不同设备的并发调用各自独立。全部本地及远程宿主请求通过有界工作线程执行，每个插件最多 16 个，等待文件选择或网络不会阻塞 Core 读取该插件的其他响应；插件后端自身是否并发仍取决于其实现。跨插件调用也传递设备、取消与父调用期限。需要当前设备交互的派生任务保留所属调用的 `HostClient`，不要使用跨调用缓存的客户端处理文件交互；进程定时器／恢复任务使用 startup 稳定客户端，不继承旧远程设备身份。

插件使用 manifest v3，并在 `backend` 中声明 `"supportsServiceContext": true` 才能远程调用。自实现协议的后端必须把请求中的可选 `serviceContext` 原样带到对应的 `core.*` 请求中；普通本地调用可省略该字段，但同进程有远程调用时不能丢失交互上下文。富文本编辑器已补上透传，其余维护插件使用当前 SDK。不要给未更新的二进制单独添加此声明。

当前 Core 将旧 manifest v1/v2 包保留并标为不兼容，不运行旧 API。`core.browser.open_official` 及旧服务发现方法已删除，插件需更新当前方法和共享 `FileResult` 契约后重建。`local/saved` 表示已写入宿主机文件，`remote/ready` 只表示生成完成并等待下载，不保证浏览器磁盘保存；远程 `export_dir` 返回 `DIRECTORY_UNAVAILABLE`，不提供主机目录。正式发布配套插件时须把 `minCoreVersion` 提升到承载当前契约的 Core 版本。已有业务数据和密钥按 pluginId 保留，导入会按插件原有逻辑更新这些数据。

## CLI

命令必须发送到正在运行的桌面 Core；可用全局 `--data-dir <绝对路径>` 指定独立测试 profile。

```powershell
# PowerShell 7 示例；按实际安装位置调用 wla.exe。
$webOptions = @{
    mode = 'loopback' # 或 'lan'
    port = 17890
    publicUrl = 'https://core.example.com/' # 不使用公网时为空字符串
    accessKey = '' # 可选；非空时要求设备提供此密钥
    pluginIds = @('rich_editor') # 必须已经安装、启用并声明远程支持；可以待用
} | ConvertTo-Json -Compress
wla web start --config-json $webOptions --yes
wla web status
wla web stop --yes
```

`start` 和 `status` 输出在配置认证时包含访问密钥，勿保存到共享日志。局域网模式下还返回 `lanAddresses`（网卡名、IPv4、完整 URL）；枚举失败时返回 `addressError`，服务本身仍可继续运行。`stop` 可以重复执行；已开启时再次 `start` 会返回错误，避免意外中断已连接设备。端口占用、非法 HTTPS 入口、未安装／停用或不支持远程的插件会返回明确错误；冷态本身不构成共享失败。

## 开发与检查

```powershell
pnpm --filter @wonderland/desktop-ui run build
cargo test --workspace --locked
pnpm -r run test
pnpm dev
```

Vite 同时构建 `index.html`（桌面）和 `mobile.html`（浏览器），生产版由 Tauri 的嵌入式资源提供，无需另行部署静态目录。Debug 模式的网页服务从 `ui/dist` 读取资源，因此需先运行前端 build，修改后再次 build 并刷新手机页。

HTTP API 位于 `/api`：`GET status/plugins/launch/{pluginId}/events`、`POST call/cancel`。配置密钥时使用认证头；未配置时允许直接访问已共享插件。普通请求体 256 KiB、最多 16 个并发插件调用；事件缓存 256 条、每条 64 KiB。这些是单消息／队列预算，不是文件总量上限。插件资源使用独立授权和 opaque iframe，允许表单、媒体、前端联网和外链，包内脚本与 Bridge 身份边界仍保留，完整 UI 架构由独立文档仓库的 `docs/PLUGIN-UI-ARCHITECTURE.md` 维护。

远程文件通过 `GET interactions`、`POST interactions/{id}/reply`、下载 prepare 和 `GET selected-files` 管理；文件交互不进入共享业务事件流。普通请求携带当前 owner 的 `X-Wonderland-Client`，下载使用上述专用 Cookie。reply 请求体上限 2 MiB，以容纳 1 MiB 文件分块的 base64。

回归检查包括：无密钥直接连接、配置密钥后错误密钥被拒绝、连接记录恢复与失效清理、白名单隔离、路径限制、密钥撤销、旧请求不影响新连接、插件沙箱加载与实际读写，以及 390px 手机和宽屏工作区显示。真实公网可达性还取决于实际部署的域名、TLS、代理与网络环境。
